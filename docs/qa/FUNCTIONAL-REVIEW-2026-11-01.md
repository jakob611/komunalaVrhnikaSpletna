# Functional review — 1 November 2026

This report records the earlier implementation/functional pass. The subsequent product review and authorized deployment are tracked in [RELEASE-2026-11-02.md](RELEASE-2026-11-02.md).

Review started on 1 November; final fixes and verification continued on 2 November 2026.

The earlier project audit concentrated on security, architecture, data integrity and selected browser workflows. It did **not** establish that every guest and administrator action worked end to end. This follow-up inventories the identified user actions, exercises their important success/failure paths, fixes confirmed defects, and records the remaining acceptance work.

The three inventories contain **164 action/state groups**. This is a review index, not a count of JavaScript functions or 164 independently browser-certified workflows.

## Remaining acceptance work and practical limits

The inventories retain explicit gaps instead of treating a passing build as complete usability certification. In particular:

- Physical phone/touch, Safari/Firefox, keyboard-only journeys across every editor, assistive technology, physical printer output, native calendar installation and external provider account completion still need acceptance checks. Calculator print preview was checked locally as described above; it does not certify every printer setting or custom content length.
- Real GPS permission/accuracy, every map pointer transformation, cemetery plan replacement/row placement and the physical grave register require appropriate device/source validation.
- Live invitation/authentication/subscription messages, provider acceptance versus destination inbox delivery, production cron activation and operational backup/restore remain deployment checks. No live campaign was used for testing.
- Campaign previews protect the notice revision but evaluate the audience again when queueing. The UI now explicitly explains that the final audience can change. Terminal failed mail is visible; an explicit staff retry/resume action is not implemented.
- Unsaved operational recovery lasts within the same open page. Reload/crash persistence for private case notes is not implemented. Private CMS drafts are server-backed.
- Work/subscriber SQL search has literal matching and tested ASCII case behavior; uniform Unicode case/diacritic equivalence is not promised.
- Erasure covers the application's records and storage, not delivered mailbox copies, independent business records or backups. Large erasures have documented bounds. Actual retention and backup policies remain an operator decision.

The functional gaps above are distinguishable from confirmed defects already corrected. This review materially improves reliability and makes the remaining work reviewable; it is not a claim that every possible state on every device has been manually certified.

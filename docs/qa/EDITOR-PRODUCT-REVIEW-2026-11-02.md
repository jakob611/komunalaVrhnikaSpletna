# Editor purpose and address-domain review — 2 November 2026

This is a bounded second review of the **purpose, wording and consequences** of every AE01–AE63 feature family. It complements `ADMIN-EDITOR-2026-11-01.md`, whose individual rows retain the precise executed-test limits. KEEP means the current feature has a coherent purpose; it does not certify every field by browser testing. FIXED means a reproduced issue has a source change and regression evidence. OPERATOR means actual service data or editorial responsibility is needed from KPV; code must not invent the answer. Authentication, account permissions, email/media operations and schedule failure handling also have the separate operations review.

## Address fixes and realistic regression matrix

Reproduced before this pass: collection lookup accepted `Verd 12/1, Vrhnika` and `Verd 12–14, Vrhnika` as a definite address, whereas notification targeting rejected such ambiguous forms. Collection rules also lacked the notification parser's common `c.` / `ul.` and `48-a` spelling normalization. This allowed inconsistent preview/delivery behavior.

The shared input normalization now accepts street abbreviations, case/diacritics, spaced or hyphenated letter suffixes and normal postcodes. Both matchers reject slash/range notation, including suffix ranges and the word `do`; they never reinterpret `12/1` as either house 12 or house 1. Users can supply an explicit apartment component, e.g. `Verd 12, stanovanje 1, Vrhnika`. Publication rejects ambiguous collection rules. The admin address help and test preview explain the correction. Existing explicit house/suffix and locality boundaries remain in place.

`shared/address-domain-audit.test.mjs` contains 26 paired collection/notification cases, qualified/unqualified route cases, publication rejection cases and explicit district/topic/status gates. Cases distinguish house 48/480/48a, contradictory towns and street types, Log/Logatec/Dragomer, Lukovica pri Brezovici/Domžalah, full compound settlements, diacritics, postcodes and explicit apartments. The matrix deliberately uses synthetic houses and does not assert that a particular real-world building exists or belongs to an official route. Existing official-route integration covers Verd, Log, wrong-town rejection, ambiguous vehicle routes, partial coverage and expiry. A subscriber's manually chosen district is not inferred or overwritten by address text.

`src/test/admin-address-audit.test.tsx` additionally exercises invalid slash address → explanatory error → corrected apartment address → three independent fractions, and an imported range rule → replacement by separate houses. It asserts the draft/public distinction. Tests perform no external data writes or delivery.

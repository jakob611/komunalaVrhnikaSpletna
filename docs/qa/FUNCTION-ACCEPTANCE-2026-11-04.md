The HTTPS feed also imported through Google’s From URL form. The updated portal includes both paths and explains the first-import delay. ## Release verification on 5 November

The clean integrated run passed 201 server/shared tests and 208 UI tests. The production build, TypeScript check and Wrangler deployment dry run passed. Earlier concurrent runs exceeded test time limits under heavy host load. The affected guest cases then passed unchanged in isolation and in the full suite. Four additional editor control tests also passed. The production dependency audit reported zero known vulnerabilities.

Application commit `fbc252431f6f2165c64f601b966c716ccf329618` was pushed and deployed as Cloudflare Worker version `b36d5170-d632-44be-ad28-96dc155520ec`. Both [push CI](https://github.com/jakob611/komunalaVrhnikaSpletna/actions/runs/41973979292) and [PR CI](https://github.com/jakob611/komunalaVrhnikaSpletna/actions/runs/41973985226) passed. The first immediate requests reached the previous deployment during propagation. Repeating the same checks after propagation passed all 113 calendar requests and 21 release assertions, including byte-identical copies of all 15 JavaScript bundles, the three Borovnica examples, unchanged CMS content and anonymous admin rejection. Production smoke passed collection, calendar, Turnstile rejection and cross-origin protection. Market submission was skipped because no future market dates are published.

The 27-table read-only data check found 26 empty tables and one newer authentication audit record. Operational submissions, tasks, subscribers and publication history remained empty. The authentication record was preserved because new production activity must not be indiscriminately erased. No production test submissions were created. The temporary public calendar QA Worker was deleted after testing.

Browser control returned on 5 November. A genuine local owner password/OTP login succeeded. The updated admin preview rejected `Verd 99999` and showed the three expected fraction routes and dates after selecting the registered `Verd 12, Vrhnika` option. A native confirmation later blocked the automation, and the first pass stopped.

The resumed browser pass completed the deployed portal-to-Google journey. A single BIO event was saved with the correct all-day date and then removed with Undo. The repeating button added the exact production feed, which displayed the expected 10, 17 and 24 November and 1 December dates. All temporary Google KPV subscriptions were identified by their source URLs and removed. The live copy fallback copied the exact HTTPS URL.

The browser also exercised 390- and 320-pixel layouts, mobile menu navigation, search results and Escape focus return, calendar dialog scrolling and dismissal, report map selection/cancellation/confirmation/removal, collection-point search and directions, and desktop skip/submenu keyboard focus. These are emulated viewports, not physical touch or GPS tests. The calculator and long-name header overflow findings above came from this pass.

Additional isolated admin browser checks generated 52 weekly dates, deduplicated repeated additions, retained selection across event pages, rejected a colliding move and moved two selected dates safely. Tariff editing retained separate municipality values through a transient blank edit. Actual local publication changed the public calculator example from 75.83 to 77.14 euros when the water rate rose by 0.1 euros per cubic metre; the original rate was then restored. Cemetery controls created sectors, rows and places, found a secondary occupant across sectors, placed one grave on the actual SVG, cancelled a pending row placement without changing positions, and placed the four graves of the selected row without positioning the other sector. Private drafts saved successfully. The admin panels stayed within 390 and 320 pixels, with the larger plan confined to its own scroll area. Native confirmation acceptance/cancellation remains a browser-tool boundary; no successful outcome is claimed.

The audit accounts for all 164 action groups using the stated browser, rendered-component and HTTP evidence. It does not certify every device/provider or every browser variant. KPV must still supply house-level assignments where its source schedules overlap between ordinary and small collection vehicles. The portal reports that ambiguity instead of choosing an unsupported route.

# Administration editor functional QA — 1 November 2026

Bounded upload follow-up completed on 2 November 2026 (Europe/Ljubljana).

This is an action/state inventory, not a claim that every interaction has been exercised in a real browser. This reviewer inspected the implementation and ran component and server tests; the primary reviewer owns the shared browser. No production content or remote account was changed for these checks.

**PASS (component)** means an action was exercised against React in jsdom with its resulting data/assertions checked. **PASS (integration)** means server/domain behavior was exercised with SQLite/D1 or workerd as identified. **UNTESTED** means source inspection alone is insufficient to certify the interaction. This reviewer did not operate the shared browser; specific browser evidence supplied by the primary reviewer is attributed in AE27, AE38 and AE62 and consolidated in `FUNCTIONAL-REVIEW-2026-11-01.md`. A functional PASS does not certify all mobile layouts, keyboard comfort, assistive technology, real email delivery, or physical cemetery accuracy.

## Defects reproduced during this pass

1. **AE01 — custom-page reset deleted the page.** The reset action removed its entire `layout.pages` entry while retaining navigation links to it. Approved fix now resets its blocks while preserving path/title/menu destination. New component regression passes. Built-in pages retain their original reset behavior.
2. **AE03 — notice address targeting showed an older draft after import/recovery.** `addressText` only refreshed when selection changed or the draft became clean. Approved fix tracks the last locally emitted address-rule signature, updates on external same-ID rule changes, and preserves raw blank lines while typing. New component regression passes. This avoids accidentally replacing restored household rules with stale visible text.
3. **AE28 — exported large website JSON could not be reimported.** The file control had a 2 MiB cap despite the normalized website snapshot supporting up to five individually bounded 1 MiB sections. Approved fix enables the website advanced dialog, allows website files up to 6 MiB (other sections retain their 2 MiB cap), and validates parsed content before replacing the current draft. The security/recovery reviewer reports a passing component regression, AO49 in `src/test/admin-operations-audit.test.tsx`, covering a >2 MiB export/import/apply/reopen roundtrip and rejection of invalid files without replacing prior state. The primary reviewer separately exercised native browser export/import/apply for settings; the large website roundtrip remains component evidence.
4. **AE19 — late image uploads could overwrite newer drafts or resurrect deleted blocks.** Reproduced failures showed that WebsiteEditor discarded a second image/branding edit, LayoutEditor discarded a second block/menu edit and recreated a removed image block, and CemeteryEditor allowed an older upload to replace a newer plan. Fixes merge against current draft refs using the original target identity, skip removed custom targets and unmounted editors, and ignore superseded cemetery uploads. Cemetery plan application retains the current dimensions/graves and still follows the existing verified-position confirmation flow. Ten focused upload regressions pass, including full AdminPage failure → same-file retry. Concurrent race cases are component tests; the parent's busy flag reduces normal concurrent input and these are not claimed as manually reproduced browser races.

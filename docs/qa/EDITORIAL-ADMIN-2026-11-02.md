# Admin wording review — 2 November 2026

Reviewed the admin workflow families and made focused Slovenian copy changes in 16 admin components and `AdminPage.tsx`. No handlers, permissions, data shapes, field IDs, numeric limits, prices or business rules changed. No tests were edited; no production writes, commit or deployment were performed by this review.

## Concrete changes

| Family | Before → after | Reason |
| --- | --- | --- |
| Sign-in and enrollment | “Dobrodošli nazaj.” → “Prijava v uredništvo”; “Preverite svoj predal.” → “Vnesite prijavno kodo” | Name the current task. Enrollment success now explicitly directs the user to sign in with the new password and then enter the new emailed code. |
| Dashboard | “VSE NA ENEM MESTU / Urejena stran. Urejene informacije.” → “ZAČETNA STRAN / Urejanje portala” | Replace decorative slogans with a useful heading. Instruction asks staff to verify data and preview before publication. |
| User access | “Vsak urednik ima svoj dostop.” → “Uporabniki in dostopi”; “Dodajanje ljudi ostane lastniku.” → “Nove urednike lahko povabi samo lastnik.” | Concrete administration language. The owner badge states that owner's access cannot be revoked; changed-scope notice requires a fresh login. |
| Drafts and publication | “Vsebina je shranjena” → “Prikazana je objavljena vsebina”; notice instructions distinguish “Shrani osnutek”, “Shrani in objavi” and separate email sending | Avoid confusing personal drafts with public content. The notice guide explains that publication saves the whole list and shows entries with enabled public display. |
| Notices | “Datum … ne določa časa objave; … po shranjevanju” → explicit “Shrani in objavi” action | A notice's displayed date is not its publication schedule. Unpublishing an existing notice now has explicit checkbox-plus-publication instructions. |
| Campaigns | “Ujemajoči potrjeni naročniki” → “Potrjeni naročniki za to obvestilo”; “ciljanje” → “izbrana območja, naslove”; “trajna čakalna vrsta” → “čakalna vrsta” with refresh-button instruction | Remove internal terminology while retaining current-preview versus final-audience warning, duplicate prevention, terminal failures and provider-acceptance limits. Empty state directs staff to the content editor who must publish an eligible notice first. |
| Subscribers and districts | Historical “stari zapisi / nove prijave” wording → current subscription status, selected topics and confirmation requirement | Explain the live task without framing the product as a migration/test site. Still states that an old work-queue record alone is not a confirmed subscription, and preserves 50-row navigation/search guidance. District selection/description and deactivation warnings were reviewed and retained. |
| Work queue | “OD PRIJAVE DO REŠITVE” → “OBRAVNAVA ODDAJ”; technical recovery warning → plain instruction to review restored changes and reload if another editor changed the case | Keep actionable instructions for received submissions, internal tasks, responsibility, dates and closure. Sent-email label now means acceptance by the email provider and explicitly does not prove inbox receipt; provider brand is unnecessary here. |
| Private recipient | Technical “obnovljen … na strežniku” wording → review restored address and reload if another value was saved | Explains conflict recovery without database terminology. The introduction also says submissions remain accessible in the work queue. Existing warnings about queued messages retaining their old recipient and unchanged login addresses remain. |
| Scheduling | “Posnetek osnutka … slovenski datum” → current draft saved for publication on the chosen date in Slovenian time | States that later draft changes do not change the scheduled content, conflicting public edits stop publication for review, and a published notice still needs separate email sending. |
| Privacy | “Orodje za lastnika … vlagatelja” → “Izbris lahko izvede samo lastnik … prosilca”; “sprememba obsega zahteva nov predogled” → review again if data changes | Preserve identity/basis checks, permanent deletion, ten-minute validity, external/provider/backup exclusions and absent automatic retention policy. The irreversible checkbox and action label remain explicit. |
| Media, website and layout | “Pripravite prvo sliko.” → “V knjižnici še ni slik” with upload action and no-publication explanation; new-page instructions name “Shrani in objavi” | Clarify that uploading alone does not put a picture on the website and creating a page still requires publishing and a discoverable link. Existing repeated-text/image/global-element warnings remain. |
| Editor failure and JSON | “Osnutek je ohranjen” → “Osnutek je še v tem oknu” plus copy-before-reset warning; JSON instructions name the final publication button | Avoid implying durable storage for an in-memory draft. Reset explicitly replaces the current draft. JSON import first changes the form, not the public site. |
| Collection, cemetery and tariffs | Repetition wording → calendar contains published dates and downloaded file is not updated; “potrjeni grobovi” → “grobovi s potrjenim položajem”; “Cene z jasnim virom in datumom” → “Ceniki za izračun in posebne storitve” | Concrete operational terminology. Retained address ambiguity/vehicle distinctions, public-record/privacy checks, unpositioned graves, tenant-contact restriction, VAT bases, source/effective-date and historical-calculation limits. |

## Families examined and retained

The review included sign-in/code/enrollment, invited/active/revoked users and scopes, dashboard/navigation, each generic CMS field/list editor (settings, hours, waste points/items/categories, services, stall rates and market dates), website text/image/link/logotype editing, page layout/navigation/custom pages, media library and image picker, notices/districts/subscribers/campaigns, work list/detail/filter/checklist/history, recipient settings, private drafts/history restoration/JSON import-export, scheduled publication, privacy preview/erase, collection rules/events/repetition/exceptions/address preview, cemetery sectors/rows/graves/people/background/positions, tariffs and numeric input/validation, location picker and editor recovery.

Existing short labels and necessary domain terms were kept where already clear. No official contact details, prices, taxonomy, data source claims, authorizations, legal policy or retention periods were invented. `NumericInput`, shared draft validation, district editor and location picker required no copy changes. Server-provided validation/error messages were outside the owned files and were not rewritten here.

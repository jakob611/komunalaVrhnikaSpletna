# Admin operations functional audit — 1 November 2026

This inventory covers authentication, permissions, work handling, subscribers, notification delivery, owner settings, erasure, and scheduling. It supplements the separate guest and content-editor inventories. Tests use synthetic local SQLite records and private test mailboxes. No real invitation, campaign, public submission, erasure, production database change, or external email was performed by this audit.

The [2 November product/workflow ledger](ADMIN-OPERATIONS-PRODUCT-REVIEW-2026-11-02.md) maps every AO group to its purpose, steps, necessity and missing behavior. Its final focused follow-up adds nine release UI tests covering destructive preview invalidation, schedule status recovery, terminal campaign guidance and operations-only subscriber/topic access. Those tests and the relevant editor/operations suites passed together (59 UI tests); TypeScript passed. This is separate from the earlier inventory cohort recorded below.

**Verification recorded:** 75 tests passed in the nine backend files listed below; 26 tests passed across the four UI files listed below. The new audit files contribute six API workflow tests and eleven DOM workflow tests. TypeScript checking passed. A DOM test establishes component behavior; it does not establish real browser layout, delivered email, or external provider behavior. The primary agent owns browser verification separately.

## Fixed during this operations pass

1. A lost task-create response followed by a changed assignee, priority or due date previously returned the original task with 201 and silently ignored the new fields. The complete original creation request is now compared, so a changed retry returns 409 while a byte-equivalent semantic retry remains safe after later case edits.
2. Case notes and new-task inputs previously disappeared when a 401 unmounted WorkQueue. Parent-held, account-bound memory now preserves them through same-person reauthentication. The private payload is not copied to localStorage or sessionStorage. Explicit logout, accepted navigation/discard, a different account and removal of operations access clear recovery state.
3. Direct requests in campaign delivery, subscriber overview and privacy tools now trigger the same reauthentication path. Owner notification recipient edits also retain their value and revision baseline in account-bound memory.
4. Website advanced import/export is available again, accepts valid combined snapshots over the old 2 MiB cap, validates file contents before replacing editable JSON, and preserves the current draft after invalid input.

5. The subscriber overview no longer stops permanently at its newest 50 entries. Older/previous pages and bounded email/address search are available. A 120-record district fixture with identical timestamps confirms complete pagination without tied-row duplicates, and the DOM test reaches older records and resets pagination when filters change.

6. Explicit logout now treats a 401 as an already-ended server session and discards all local recovery after the user accepts the unsaved-change warning. A later login by the same person cannot restore that discarded task. A 503 or network failure leaves the current authenticated view and unsaved input available and displays an error without a false sign-out confirmation. Ordinary save-time 401 still retains same-person recovery.

## Remaining limits and deployment/user acceptance checks

- This pass does not certify every physical browser interaction. Native dialog focus, keyboard dismissal, phone layout, file download, invitation links and real email delivery remain separate browser/provider checks.
- Subscriber pages use a stable `(updated_at,id)` cursor and 50-row batches. Email/address search is bounded to 254 characters and treats SQL wildcards literally. District counts remain totals for the selected district rather than search-result totals. Concurrent edits can move records between pages; refreshing deliberately restarts at the newest page.
- Final failed notification delivery has visible status, but no staff retry button. Identical cancelled/completed campaign versions remain deduplicated; there is no explicit resume/re-send workflow for the same version.
- Campaign dispatch evaluates the audience at queue time; changes between preview and send can change the count. The delivery panel now states this explicitly. The notice revision is protected, while the recipient count is not an approval-bound audience snapshot.
- Work search is a SQLite `LIKE` search. ASCII case and literal wildcard behavior are tested; consistent Unicode case/diacritic matching is not established. Do not advertise accent-insensitive work search on the strength of the cemetery/notice search implementation.
- Work/recipient recovery survives reauthentication in the same open page. A page reload, browser crash, explicit logout or accepted discard does not persist those private unsaved inputs. This is intentional; server-backed private draft retention for operational cases is not implemented.
- Erasure does not delete provider mailbox copies, recipients' messages, independent business records or backups. No automatic retention period was invented. The operator must approve actual retention/backup procedures.
- Authentication mail, Resend acceptance, true destination mailbox delivery and production cron execution were not exercised against real users. The local audit uses fake recipients and injected delivery responses only.
